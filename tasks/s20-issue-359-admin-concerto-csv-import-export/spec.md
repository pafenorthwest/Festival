## Approach
1. **Preflight & Isolated Worktree**:
   - Confirm `S16` (`13ebbd0`) is `DONE` on `origin/main` and validate `s20-issue-359-admin-concerto-csv-import-export` via `validate-packet.ps1` (exit `0`).
   - Branch `feat/s20-issue-359-admin-concerto-csv-import-export` off `origin/main` in an isolated worktree so `S20` executes concurrently with `S17`–`S19`.
2. **Rule 1 — RFC 4180 CSV Format, Template/Export & `work_id` Round-Trip (`concerto-repertoire-csv.ts`)**:
   - Enforce exact UTF-8 header `work_id,title,composer,imslp_url` (stripping optional UTF-8 BOM `\uFEFF` on upload) with strict RFC 4180 quoting/unescaping for commas, double quotes (`""`), CRLF/LF line breaks, and Unicode characters.
   - `GET /api/organizations/:slug/admin/concerto-repertoire/template` returns `work_id,title,composer,imslp_url\n` (`text/csv; charset=utf-8`, `Cache-Control: no-store`).
   - `GET /api/organizations/:slug/admin/concerto-repertoire/export` exports only active canonical works in the authenticated organization that carry the `'concerto'` classification, ordered deterministically (`lower(display_title) COLLATE "C", display_title COLLATE "C", id COLLATE "C"`).
   - Exported files (including `database/bootstrap/pafe-concertos.csv` where `pafe-bootstrap-work-21` and `pafe-bootstrap-work-22` have distinct `work_id`s with identical `(title, composer)`) re-import with `0` changes and `0` duplicates, while duplicate `work_id`s in the same CSV, multiple rows resolving to the same work, unknown/cross-org/non-`concerto` `work_id`s, and ambiguous blank-`work_id` `(title, composer)` matches are reported with 1-based row numbers, field names, and actionable reasons.
3. **Rule 2 — Composer-Aware Matching & Shared-Contributor Safety (`concerto-catalog-csv-queries.ts` & `concerto-catalog-csv-service.ts`)**:
   - Do **NOT** call title-only `upsertWorkTx` in `repertoire-catalog-repository.ts` (which matches on `normalized_title` alone).
   - For blank `work_id`: match on `(organization_id, normalized_title, primary_composer_normalized_name)` across active canonical works in the organization. Keep same-title concertos by different composers as separate canonical works; reuse an existing matching work in the org and attach `'concerto'` if missing; insert a new `repertoire_works` row with a server-assigned UUID when unmatched; reject if `>1` existing works in the org match `(normalized_title, primary_composer_normalized_name)` when `work_id` is blank.
   - For nonblank `work_id`: verify the ID exists in the organization's current `'concerto'` catalog; detect field-level changes to `display_title` (`normalized_title`), primary composer (`position = 1`), or `imslp_url`. When primary composer changes, upsert/lookup the target `(organization_id, normalized_name)` row in `orgs.repertoire_contributors` (updating `display_name` on a contributor row **only** if no other work in `orgs.repertoire_work_contributors` references that contributor ID, otherwise creating/linking the target contributor record without renaming the shared record) and re-point `orgs.repertoire_work_contributors` at `position = 1` while preserving `position > 1` contributors, other classifications, and `work_id`.
4. **Rule 3 & Rule 4 — Classification-Only Removals, Clear-All Gate & Digest-Verified Atomic Transaction**:
   - `POST /api/organizations/:slug/admin/concerto-repertoire/preview` runs in read-only mode (`0` writes) and returns `{ valid, errors, summary, added, updated, unchangedCount, removed, clearsEntireCatalog, catalogDigest }`.
   - Omitted concerto works never delete `orgs.repertoire_works` rows, non-`'concerto'` classifications, contributor rows, or historical `orgs.registration_repertoire_items` / `orgs.repertoire_review_items` references—only their `(organization_id, repertoire_work_id, concerto_classification_id)` row in `orgs.repertoire_work_classifications` is removed.
   - A valid header-only file sets `clearsEntireCatalog: true` (when current catalog is non-empty or empty, explicitly flagging clear-all outcome in preview) and requires `confirmClearAll: true` on `POST /api/organizations/:slug/admin/concerto-repertoire/import` (`400` with `0` writes if omitted).
   - `POST /api/organizations/:slug/admin/concerto-repertoire/import` acquires `pg_advisory_xact_lock(hashtextextended($1, 0))` for `concerto-csv:${organizationId}` inside `sql.begin`, recomputes `catalogDigest` against current DB state (`409` `stale_catalog_preview` with `0` writes on mismatch), re-validates the CSV (`400`/`422` with `0` writes on any row/header error), applies all inserts, updates, and `'concerto'` classification deletions in that single transaction, and emits `RepertoireUpdated` on `DomainCacheInvalidator`.
5. **Admin Concerto Repertoire UI & Full Verification (`<= 500`L/file)**:
   - Add `/org/:slug/admin/concerto-repertoire` (`org-admin-concerto-repertoire`) in `routePaths.ts`, `routes.ts`, `lazyPages.ts`, `createFestivalAppState.ts`, `useFestivalLifecycle.ts`, and `AdminRoutes.tsx`, plus a **Concerto Repertoire** workflow card on `AdminHomePage.tsx` (`disabled={!props.app.isAdminMember()}`).
   - Build `AdminConcertoRepertoirePage.tsx` + `adminConcertoRepertoireHelpers.ts` providing: **Download Blank Template**, **Export Current Concerto CSV**, file picker / CSV upload -> **Preview Replacement**, clear summary & tables for row errors (`row`, `field`, `reason`), `Added`, `Updated` (before/after fields), `Unchanged`, and full `Removed` list, an explicit clear-all warning + confirmation checkbox when `clearsEntireCatalog` is `true`, and **Confirm & Replace Concerto Catalog** wired with `expectedCatalogDigest`.
   - Execute full unit, route/NGINX security, boundary/ratchet, and PostgreSQL 17 integration suites (`0` warnings, `0` errors).
