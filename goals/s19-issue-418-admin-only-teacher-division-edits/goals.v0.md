# Goals Extract
- Task name: s19-issue-418-admin-only-teacher-division-edits
- Iteration: v0
- State: locked

## Goals
1. Remove customer post-creation Teacher division editing across `@festival/common`, backend routes/services, and Customer Account UI: split `UpsertCustomerTeacherProfileInputSchema` to `{ displayName, publicDirectoryOptIn }` so `PUT /api/customer/orgs/:orgSlug/profiles/teacher` rejects `divisionIds` (and any unknown field) with `400` without mutating assigned divisions; seed initial `divisionIds` server-side from the customer's active `teacher_membership` grant(s) when `existing === null` and preserve `existing.division_ids` on all subsequent customer Teacher profile edits; and render assigned Teacher divisions read-only (without checkboxes) on `/org/:slug/account/memberships` while keeping `"Public Teacher Directory"` heading text and creation-time selection on `MembershipPage.tsx` intact (`#418` `AC #1`–`#4`, `#7`).
2. Add an Organization-Admin-only Teacher division editing endpoint `PATCH /api/admin/orgs/:orgSlug/profiles/teachers/:profileId/divisions` (`requireAuth`, `requireTenant`, `requireTenantRole(["Admin"])`, `authenticationClass: "admin"` in `PARTICIPANT_PROFILE_ROUTE_SECURITY`, NGINX `PATCH` allowlist, `404` on unknown or cross-org `profileId`, requiring **strictly `1` active organization division (`divisionIds` length `1`)** per locked `D6`, preserving `approval_status` and emitting `TeacherDirectoryChanged`) plus a single-division Admin editor UI in `AdminTeacherDirectoryPanel.tsx` / helper subcomponent (`<= 500` lines/file) (`#418` `AC #5`, `#6`, `#8`).
3. Keep `orgs.membership_entitlement_divisions` immutable in PostgreSQL (`0` DB migrations) as historical purchase evidence while resolving a Teacher's effective active division(s) in `listCustomerMembershipStatus`, `listActiveTeachersForDivision`, `findActiveTeacherEntitlementGrant`, and `loadActiveTeacherRoster` from `orgs.teacher_profile_divisions` whenever a `teacher_profiles` row exists for `(organization_id, customer_id)` (falling back to `orgs.membership_entitlement_divisions` only when no `teacher_profiles` row exists yet), so Admin division corrections reflect consistently across Account `Memberships`, Account `Public Teacher Directory` (read-only), Admin panel/roster, registration Teacher picker/eligibility, and `/org/:slug/directory` (`#418` `AC #6`).
4. Enforce the organization's configured Accompanist division policy (`exactly_one`, `one_to_two`, `one_to_all` via `validateMembershipDivisionSelection`) in both `ParticipantDirectoryService.upsertAccompanistProfile` (`400` without DB mutation when out of policy or referencing inactive/foreign divisions) and the Customer Account Accompanist directory card UI, preserving independent permissions for dual-role accounts holding both Teacher (read-only divisions) and Accompanist (policy-bounded editable divisions) memberships, and pass full unit, browser, route/NGINX security, and PostgreSQL 17 integration verification (`#418` `AC #8`–`#11`).

## Non-goals
- Editing runtime or test files before `S18` (`s18-issue-416-accompanist-public-directory-parity`) merges to `origin/main`.
- Changing creation-time Teacher division rules on `MembershipPage.tsx` (`#172`).
- Mutating historical rows in `orgs.membership_entitlement_divisions` or adding any SQL migration under `database/`.
- Restricting Accompanist post-registration division edits beyond the organization's configured Accompanist division policy (`exactly_one`, `one_to_two`, `one_to_all`).

## Success criteria
- [G1] `UpsertCustomerTeacherProfileInputSchema` accepts only `{ displayName, publicDirectoryOptIn }`; `PUT /api/customer/orgs/:orgSlug/profiles/teacher` rejects `divisionIds` with `400` leaving stored divisions unchanged; first-time `upsertTeacherProfile` seeds `division_ids` server-side from active `teacher_membership` grant(s) while subsequent customer edits (`displayName` / `publicDirectoryOptIn`) preserve `existing.division_ids`; `CustomerTeacherDirectoryCard.tsx` renders Teacher divisions read-only without checkboxes (keeping `"Public Teacher Directory"` heading); and `MembershipPage.tsx` creation-time division selection still works.
- [G2] `PATCH /api/admin/orgs/:orgSlug/profiles/teachers/:profileId/divisions` enforces `Admin` role in the target organization (`401` unauthenticated, `403` non-admin member, `404` cross-org admin or missing profile, `400` when `divisionIds` does not contain strictly `1` active organization division—rejecting `0`, `>1`, duplicate, invalid UUID, inactive, or cross-org division IDs without DB mutation), is declared in `PARTICIPANT_PROFILE_ROUTE_SECURITY` and NGINX configs, preserves `approval_status`, emits `TeacherDirectoryChanged`, and is wired to a single-division Admin UI selector (`<= 500` lines/file).
- [G3] `orgs.membership_entitlement_divisions` remains untouched in PostgreSQL after an Admin Teacher division edit, while `listCustomerMembershipStatus`, `listActiveTeachersForDivision`, `findActiveTeacherEntitlementGrant`, `loadActiveTeacherRoster`, `CustomerAccountMembershipsPage.tsx`, `CustomerTeacherDirectoryCard.tsx`, `AdminTeacherDirectoryPanel.tsx`, and `/org/:slug/directory` all resolve effective active Teacher division(s) from `orgs.teacher_profile_divisions` whenever a `teacher_profiles` row exists (falling back to `orgs.membership_entitlement_divisions` only when no `teacher_profiles` row exists yet).
- [G4] `ParticipantDirectoryService.upsertAccompanistProfile` and the Customer Account Accompanist directory card enforce `exactly_one`, `one_to_two`, and `one_to_all` via `validateMembershipDivisionSelection` (`400` on violation with zero DB mutation); dual-role Teacher + Accompanist accounts see read-only Teacher divisions alongside editable policy-bounded Accompanist divisions; all modified production files stay `<= 500` lines; and full unit, browser, route/NGINX security, and PostgreSQL 17 integration suites pass with `0` errors and `0` warnings.
