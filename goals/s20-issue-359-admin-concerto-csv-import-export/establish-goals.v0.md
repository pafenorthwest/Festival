## Goals
1. Implement a shared RFC 4180 UTF-8 CSV contract (`work_id,title,composer,imslp_url`) and Admin-only endpoints (`GET` template, `GET` organization concerto export, `POST` dry-run preview, `POST` confirmed import) enforcing `requireTenantRole(["Admin"])`, strict organization isolation, route security declarations (`authenticationClass: "admin"`), and NGINX proxy allowlists, guaranteeing lossless export/re-import round-trips (including Unicode, quoted commas/quotes/newlines, and distinct exported `work_id`s such as `pafe-bootstrap-work-21`/`22`) (`#359` `AC #1`, `#2`).
2. Implement composer-aware work matching and dry-run preview validation without reusing title-only `upsertWorkTx`: resolve nonblank `work_id` strictly against the organization's current `concerto` catalog (reporting unknown, cross-org, or non-`concerto` IDs by row number and field), match blank `work_id` rows on `(normalized_title, normalized_primary_composer)` within the organization (keeping same-title works by different composers separate, reusing matching non-concerto works by adding `'concerto'`, and rejecting duplicate `work_id`s, multiple rows resolving to the same work, or ambiguous blank-`work_id` matches), and return categorized `added`, `updated`, `unchanged`, and full `removed` lists plus a deterministic `catalogDigest` with zero DB writes (`#359` `AC #2`, `#3`).
3. Execute confirmed concerto catalog replacement atomically inside a single PostgreSQL transaction (`sql.begin` + `pg_advisory_xact_lock`): re-verify `expectedCatalogDigest` against live catalog state (`409` stale preview with `0` writes) and re-validate the CSV (`0` writes on any error), require explicit `confirmClearAll` confirmation when a header-only CSV clears the catalog, update primary composer links without renaming shared `repertoire_contributors` records used by other works, remove **only** the `'concerto'` classification from omitted works (preserving canonical `repertoire_works`, other contributor roles/classifications, and historical registration links/snapshots), emit `RepertoireUpdated`, and preserve idempotency (`#359` `AC #3`, `#4`).
4. Build the Admin Concerto Repertoire UI (`AdminConcertoRepertoirePage.tsx` + helper module `<= 500`L, `concerto-catalog.ts` API client, `AdminHomePage.tsx` workflow card, and `AdminRoutes.tsx` wiring) with template download, current catalog export, CSV upload preview (additions, field-level updates, unchanged count, full removal list, actionable row/field error table, and explicit clear-all warning/confirmation), and atomic import confirmation, backed by comprehensive unit and PostgreSQL 17 integration tests with `0` errors and `0` warnings (`#359` `AC #1`–`#5`).

## Non-goals
- Modifying `database/` schema or SQL migration files (`0` DB migrations).
- Reusing title-only `upsertWorkTx` (which ignores composer identity) or mutating shared `repertoire_contributors.display_name` rows referenced by other works.
- Deleting canonical `orgs.repertoire_works` rows, non-`'concerto'` classifications, or historical `orgs.registration_repertoire_items` / `orgs.repertoire_review_items` references when works are omitted from a concerto CSV.
- Touching `teacher-directory` or Customer Account files owned by `S17`–`S19`.
